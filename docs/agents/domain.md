# Domain docs

## Layout and reading rules

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root holds domain vocabulary.
- `docs/adr/` holds architecture decision records.

Before exploring an area, read the glossary and relevant ADRs.
If these documents do not exist, proceed silently.
The domain-modeling skill creates them when terms or decisions are resolved.

If a root `GLOSSARY-MAP.md` is introduced later, follow its pointers
to the glossaries relevant to the topic.

## Vocabulary

Use glossary terms in issues, proposals, hypotheses, and test names.
If a needed concept is missing, reconsider the term or note the gap
for domain-modeling.

## Decision conflicts

Explicitly identify proposals that contradict an existing ADR.
Name the ADR and explain why the decision should be reconsidered.
