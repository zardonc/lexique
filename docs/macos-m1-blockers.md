# M1 macOS 集中验证阻塞项

状态：**blocked — 等待可用 macOS 执行环境**。日期：2026-10-25。来源：用户要求 Windows 可执行的修复先完成，必须在 macOS 运行的项目集中转移执行。此文件只记录 #10 的平台剩余项，不扩展正式发行范围。

## 已知问题与边界

`apps/desktop/src-tauri/src/vocabulary.rs` 的 `coordinate_quit` 已将菜单 Quit / Cmd+Q 转入窗口关闭协调，但该专属代码尚未在 macOS 本地编译或执行。Dock Quit 仍可能直接终止应用、绕过未保存提示；这是数据丢失风险，不能以 Windows 的通过结果或 CI `cargo check` 解除阻塞。

Windows x64 的构建入口、隔离打包、真实禁网窗口和已提交数据恢复由 [Windows 后续验证](evidence/issue-10/windows-follow-up.md) 记录。现有浏览器回调测试与 SQLite 回归保留，不作为 macOS 系统事件证据。

## 转移后按顺序执行

1. 在 macOS checkout 本次 Windows 修复后的提交，保留现有未提交文件；使用锁定的 pnpm / Rust，安装平台构建依赖。先执行 `pnpm install --frozen-lockfile`、`pnpm test:tooling`、前端检查和现有 E2E，再预编译并运行硬性 60 秒限制的 Rust 测试。
2. 使用独立测试应用标识和全新数据目录构建；应用配置覆盖只放在忽略目录，不改变正式标识或触碰既有用户库。准备固定资源的隔离副本，记录源码提交、macOS 版本、硬件架构、Tauri / WebKit、资源和程序哈希。
3. 原生执行下面的退出矩阵。先复现 Dock Quit 绕过保护，再按当前框架实际终止事件修复；避免仅调用 React 回调或重复模拟已通过的浏览器边界。
4. 在相同隔离环境禁网查询、保存空笔记 / 换行多语言笔记、编辑 / 清空、修改排序，正常退出并重启；逐项回读身份、来源、摘要、笔记和偏好。词典缺失 / 校验失败及用户库不可用也需要真实窗口验证。
5. 对 macOS x64 / ARM64 执行 locked 编译；分别记录实际运行架构。缺少另一架构设备或可核验运行渠道时，该架构保持 blocked，不能把交叉编译当作运行通过。
6. 记录截图、数据库回读和程序退出状态，恢复测试副本并停止本次程序。把结果补入 `docs/verification.md` 与关联 GitHub 任务；全部必需项通过后才解除 macOS M1 阻塞。
