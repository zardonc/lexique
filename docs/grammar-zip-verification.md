## Packaged Windows native evidence

`native-zip-source` imported three grammar records from CSV, including two same-title records and two paused cards, then exported the search and all scopes via native save dialogs. The all ZIP has three distinct names and one entry for each incoming identity. `native-zip-destination` started with an independent empty library, imported that ZIP, verified three actual SQLite identities and two paused cards, and exported CSV. `csv-roundtrip-compare-retry.log` compares all three records' exchange identity, title, body, question and answer against the original CSV. The first comparison attempt failed because the Windows Store Python alias was selected; the retry used the portable Python interpreter.

`native-source-reopen` and `native-destination-reopen` each started the packaged app on a copy of the respective persisted library and checked the three SQLite identities, two paused cards and empty review queue. `native-zip-backup` started on a copy of the destination library, created a complete backup, restored it through the app with a controlled real process restart, compared learning state, and reimported the original ZIP as existing identities. The backup scenario's `lifecycle.jsonl` records the predecessor and successor processes. A copied library demonstrates continuity of that library; only the original destination was independently initialized.

`native-zip-paths` imported renamed traversal and nested member names and coalesced an identical duplicate into three content identities. `native-zip-invalid` located and excluded a conflicting identity group and a vocabulary-template entry while committing the remaining valid entries. `native-zip-learning-retry` used ZIP input to update learned and paused cards: local categories, card identities, ratings/progress and pause state were checked, and a newly attached card was paused. `native-grammar-batch-zip-failure` induced a real second pause-write failure and checked full rollback; after retry, a failed start remained visible and paused while another card started. Native CSV batch learning, stale-preview, replay and write-failure scenarios passed separately, as did vocabulary CSV and Markdown preservation and single-Markdown invalid-template, missing-title, incomplete-pair and cancellation checks. These CSV results exercise the shared commit path; they are not ZIP-specific replay or stale-preview evidence.

Every observed fixture `cleanup.json` reported zero owned hosts, workers and helpers. The WebView context was set offline; that is not a whole-machine offline test. Other platforms, clean-machine installation and release acceptance were not tested.

## Failures and remaining native acceptance gaps

The initial `grammar-markdown-validation`, its first retry, and initial `grammar-batch-zip-learning` encountered WebView2 `ProcessFailed` access violations. The three retained Crashpad minidumps map exception `0xC0000005` to `RTSSHooks64.dll + 0x1490AF` (`minidump-diagnosis.log`); this matches the previously documented fault location, but no RTSS-disabled control or full root-cause analysis was performed. The same binary passed both scenarios in fresh retry destinations. Preserve all failed runs and dumps.

Native ZIP testing did not separately demonstrate conflicts in both entry orders, Windows normalization/case collisions, absence of extraction to archive paths, malformed/corrupt ZIP handling, or ZIP-specific stale-preview and lost-response replay. Backend and browser tests cover portions of these behaviors, but do not establish all requested packaged-native T32–T36/T37–T40 cases. The two-library round trip used an unlearned source and therefore does not independently demonstrate that source progress/history are absent in the destination. These are open acceptance gaps, not passed native scenarios.
