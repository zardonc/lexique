## 当前规则与成本来源

- `review_queue` 在调用存储队列前，读取所有未暂停、未跳过听音卡的缓存。`speech_cache::inspect` 完整读取文件，验证大小、Ogg 头及路径安全；每次还重新打开 portable 数据目录及 temp/speech 子目录。之后存储队列再次读卡片清单、逐卡读取进度、排序及应用额度。前端另读取当前听音卡的音频并等待播放成功。
- 生词本批量加入逐词等待 `addReview` 和 `generateSpeech`；每词重新打开/初始化 SQLite、提交两卡事务。生成命令受全局锁串行化，每次启动 Python、验证七份模型资源、初始化模型、合成及编码；结果作为字节数组返回前端。下一词的两卡创建因此被上一词 TTS 阻挡。
- [当前 M2 规格](../../m2-spec.md)已按用户 2026-10-31 的决定取消同词暂缓。#24 的旧措辞不应使该规则恢复：两卡独立排程，同词评分不推迟另一卡；额度、暂停、跳过、分钟级学习优先与持久顺序保持。存储仍使用真实事务，听音播放未成功不能评分。

## 测量方法与边界

环境为 Windows 11 Home 10.0.26300、AMD Ryzen 9 8945HS（8 核/16 线程）、32 GB RAM，C 盘 NTFS 位于 Micron 2400 NVMe SSD。PowerShell 7、Node.js 24.22.1、pnpm 11.25.0、uv 管理 Python 3.14.10、Rust 1.99.1，release 优化构建。只测这一台设备，未改变电源计划、系统缓存或安全软件设置。

所有数据库、音频和编译产物位于新建 `target/issue-24/` 子目录。数据为 `synthetic-*` 词头，无用户库副本。SQLite fixture 直接填充合成记录，测量通过现有公开 API 和真实 Windows 缓存读取执行；批量基线使用公开 `add_review`，事务候选仅用于实验。

队列覆盖 100 / 1,000 / 10,000 个生词（各两卡）、8 KiB 缓存，六类状态：全部新卡可到期、90% 未到期、全部未到期、两项额度为零、全部缓存缺失、25% 缺失+25% 坏头+50%有效。额外测 1,000 词半数暂停、半数听音跳过，以及 64 KiB 缓存。默认额度 20 新卡/50 复习卡，忽略复习额度开关关闭；进度场景采用固定时间和 UTC。

每个资格筛选场景交替运行基线/候选六对，第一对单独记录，后五对报告中位数及最大值。每对在独立进程中执行，SQLite 队列顺序保存到各自数据库后复用。安全目录复用对照另跑三对，后两对仅用于方向性比较，不能据此推导尾延迟。合成缓存刚写入，第一对也不是冷盘；后续为操作系统热缓存。未驱逐系统页缓存或测机械盘/USB/低端硬件。

资格筛选矩阵的部分执行与另一个隔离TTS初探重叠，因此其耗时是探索性结果，不能当作无竞争负载下的收益；确定的读取次数/字节不受此解释影响。后续安全目录复用、独立分事务和最终TTS对照串行运行，以这些结果作为首批推荐的主要时间依据。

`total_ms` 包括打开/初始化库、缓存检查、队列计算、首词读取和 JSON 序列化；不含 Tauri IPC、WebView 渲染、实际播放及后续 `cachedSpeech`。`audio_ms` 单独累计检查耗时；`logical_audio_bytes` 是固定 fixture 的逻辑读取字节，**不是物理磁盘流量**。8 KiB/64 KiB 文件只符合现有大小/Ogg 头契约，不是可解码音频，不能作为语音验收。大量历史评分、混合长期/跨日/日内卡片的性能未测。

批量 SQLite 使用默认 `journal_mode=delete`、`synchronous=2`，比较逐词打开/提交、单连接每100词提交、每500词提交，100/1,000/10,000词各三轮。TTS 比较现有打包工作进程和仅在实验进程内复用同一模型，对 `école`、`bonjour`、`œil`、`vacances`、`aujourd’hui` 各运行三轮；保留原模型哈希、法语、女声、8步、2线程、44.1 kHz 和 Opus 校验。TTS 无 IPC、缓存发布或播放。

## 方案比较与推荐

| 方案 | 收益及复杂度 | 并发、失效及行为风险 | 决定 |
| --- | --- | --- | --- |
| 一次刷新内复用安全目录句柄，仍逐文件完整检查 | 去掉重复祖先目录打开；不需要持久缓存或 schema，收益以 pinned 对照为准 | 每次刷新重新获取句柄；文件仍 nofollow/重解析点检查、完整有界读取、保留访问时间。目录句柄仅活到刷新结束 | 第一批推荐 |
| 先判定到期/时钟/零额度，再读取听音缓存 | 90% 未到期和零额度可显著减少读取；全部到期不减少读取 | 全局 `audio_pending/audio_error` 的含义改变：未到期坏缓存不再立即报错；不能直接在额度截断后过滤音频，否则缺失卡占名额且不补位 | 后续可选，不能直接接入本轮候选 |
| 每次只检查初步选出的20张卡 | 有效音频时可限制读取 | 需要按各类优先级探测并补位；最坏全缺失仍需扫描。首次持久顺序、混排比例、跨日/日内额度及音频变化必须重验 | 本轮不推荐直接实施 |
| 跨刷新缓存“音频可用”布尔值/文件存在即可入队 | 热命中最快 | 外部损坏、替换、七天清理及生成失败会失效；未验证新卡可能误入队，mtime/size不足以证明内容 | 不推荐 |
| 单连接、每100词一个短事务批量建卡 | 减少数据库打开/迁移检查、IPC及耐久提交；复用现有两卡唯一逻辑 | 每词 savepoint 保留部分成功；只能在chunk提交后报告成功。500词实测吞吐更高，100是缩短持锁的初始候选；并发响应性尚未测，不能宣称最优 | 第一批推荐 |
| 用无限并发调用现有生成命令 | 现有全局锁仍串行，不能免除每次加载模型 | 大量等待任务/IPC字节，模型内存或CPU过载，错误难以归属 | 不推荐 |
| 单个受控工作进程复用模型、逐词生成 | 摊销进程/资源哈希/模型初始化；生成本身仍有成本 | 需要消息边界、超时、崩溃恢复、取消和退出；持有模型的常驻内存本轮未量化 | 第一批推荐，按下列边界实施 |

推荐先做**安全目录复用 + 短事务批量建卡 + 建卡与语音两阶段执行并复用模型**。资格筛选候选证明了减少读取的潜力，但它改变未到期音频的全局诊断语义，且对全部到期的大批新卡没有收益，因此不原样接入。先保留当前诊断行为，实施第一批后用同一数据复测，再决定是否值得修改筛选及状态模型。

## 第一批实施步骤

1. 在 `speech_cache.rs` 提供一次刷新生命周期的检查器；首次真正检查听音卡时才打开安全目录，空库存/全跳过不额外报路径错误。共享现有读取实现，不用普通路径读取替代能力句柄，不用文件头探测替代完整校验。保留 `inspect` 不续期、播放 `read` 续期、锁/写入/清理规则。`review_queue` 复用这一检查器，队列及 IPC 响应不变。
2. 在 storage 复用 `ensure_review_cards` 和 `review_cards`，增加批量公开入口；平台验证正的JS安全整数、去重、限制总量（沿用已有10000输入界限），未知ID逐词返回失败。每100词一个立即事务，每词 savepoint，失败回滚该词，chunk提交失败不得报告任何未提交成功。已有卡片/历史/暂停/笔记完全保留；重复或丢响应后重试保持身份。先不引入schema或新的持久任务表。
3. RuntimeAdapter/Zod、Tauri命令权限和 Notebook 调用一起接入。建卡与生成分为两阶段：先返回已提交卡片和逐词失败，识义卡即可复习；成功项显示“语音待生成”，后台逐词生成并更新“可用/失败”，失败有按词重试。不得把“已建两卡”显示为“音频成功”。后端由ID取词头和偏好，不接受前端资源路径/词头；批量入口不把全部音频字节传到前端，播放沿用 `cachedSpeech`。
4. 复用现有打包运行库和 worker 校验逻辑，资源验证/模型初始化每个工作进程执行一次；使用有界、带请求身份的私有消息协议。共享一个执行通道，TTS不与SQLite事务同时持锁。批量任务逐词交出调度权，显式测试播放/重试可在下一词前服务，避免整个大批次占住全局锁；不启动每词一个进程或无限并发。输入/输出和诊断均有界，保留错误上下文，禁止把词头/学习内容写到长期日志。
5. 显示进度和“停止剩余生成”，取消在单词边界生效，正在完成的词原子发布或保留旧缓存。进程崩溃/超时清理本次子进程树，当前词失败可重试；已提交卡片和完成缓存保留。应用退出停止worker。重启后从既有卡片/缓存恢复状态，缺音频仍可通过再次加入重试，不虚报跨重启自动续跑。
6. 生成或清理期间，每次队列刷新重新检查现存文件。新卡在下一刷新进入检查范围，未经本次检查的听音卡不能入队；检查后删除/损坏仍由 `cachedSpeech`/播放失败阻止评分。原子缓存发布、失败保留旧文件及暂停独立性保持。

## 回归与前后对照

先在相同机器/电源状态、无并发性能任务时重复本目录脚本；保留首次/热缓存分组、逐次耗时和读取量。产品实施后另加真实 `review_queue` IPC→首卡渲染/播放和批量IPC→已提交卡可用的端到端时间，不能直接与本轮不含IPC的时间混比。不设未经测量的绝对延迟门槛；比对同输入输出和对应阶段成本，报告退化与剩余风险。

- 存储公开API/真实SQLite：两卡唯一、重复/丢响应重试、无效ID、部分成功、commit失败/写锁、并发评分/暂停/加入、重启进度不变；跨日/时区/时钟、零/小额度及忽略开关、日内重复、长期与跨日优先、音频失效补位、持久混排顺序。当前同词评分不暂缓另一卡。
- Windows缓存公开边界：缺失、坏头、超大小、不可写/拒绝权限、占用、文件/目录重解析点、祖先重定向、并发发布/替换/清理、读取不续期与播放续期。安全目录仅活到本次操作；验证无法取得目录时保留原始错误。
- RuntimeAdapter/UI：先看到真实建卡结果、部分语音失败/重试、取消/退出、任务身份隔离、响应乱序、暂停和已有学习数据保留、大批次进度更新合并；听音未成功播放不得评分，浏览器预览无假成功。
- 原生worker：一次初始化后的多词、缺模型/哈希失败、非法帧/截断/超大小、超时/崩溃/重启/取消、交互请求不被整个batch饿死；原生实播和断网检查独立执行，输出格式正确不等于音质验收。
- 执行README规定的lint/typecheck/build、rustfmt/check、预编译后的60秒后端测试、全套浏览器回归。产品worker或缓存安全改动需新增适用原生检查；实际WASM调度代码不改则不重做无关校准。其他平台分别验证，保留macOS/ARM64未测状态。

## 复现入口

输出路径必须是 `target/issue-24/` 下的新目录。脚本使用现有锁定依赖的Cargo artifacts编译本目录的Rust证据文件，不增加workspace target或依赖、不更改lockfile。编译与执行分开，每次执行硬限60秒并终止本次进程树；不要并行运行性能测量或其他负载。

```powershell
$perfPython = (uv python find).Trim()
& $perfPython -X utf8 scripts/measure_review.py target/issue-24/new-selection-run
& $perfPython -X utf8 scripts/measure_review.py target/issue-24/new-pinned-run --pin
```
