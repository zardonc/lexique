# 批量建卡、交互语音与网页端音频复用方案

2026-11-02。对应 [#24](https://github.com/zardonc/lexique/issues/24) 和用户追加的三个场景，已结合本轮分页、优先级、七天窗口及网页在线 TTS 草案修订。当前源码核对点为 6850ffb095a69084b02ee40a702355f660c3bd97；外部资料在本日读取。本文交付研究与实施建议，没有接入产品、执行迁移或改变平台验收结论。

用户明确说明本轮设想不是强制要求，因此草案中的“已定稿／最终确认”标题不构成新增确认。以下只把此前明确确认的 CPU 和保留规则记作要求，其他选型、删除规则及数值均为建议或待验证假设。

## 已确认要求与建议边界

| 项目 | 已确认要求 | 尚需明确的细节 |
| --- | --- | --- |
| 合成设备 | 只使用 CPU，不使用 GPU | 后台并发依设备及交互实测选择 |
| 例句音频 | 缓存 7 天 | 7 天从生成还是最后使用起算 |
| 单词音频 | 仍在生词本中的单词音频持久保留；临时查询的单词音频 7 天删除 | 删除生词、显式重新生成及旧版本的处理规则 |

这些要求覆盖历史“所有生成音频都按末次访问七天清理”的产品决定。现有实现仍执行旧清理规则，见 [缓存实现](../../../apps/desktop/src-tauri/src/speech_cache.rs)；不能把本文的确认当作已经实现。

建议采用**生成起七天的绝对有效期**，下载、播放和检查均不延长，以准确表达“仅缓存七天”；这是待确认建议。若沿用现有末次使用起七天，应明确它允许经常播放的例句长期留存。应用关闭时不能定时执行删除：过期音频不再用于播放，下一次运行再安全清理，不能承诺退出后恰好第七天完成物理删除。

## 建议收敛的方案

| 维度 | 推荐方向 | 参数及边界 |
| --- | --- | --- |
| 生词本选择 | 当前页勾选、当前页全选 | 页容量可从 20／50／100 评估；不另加“至少二十词”或重复的一百词产品限制；分页本身目前尚未实现 |
| 建卡 | 平台层短事务提交，语音异步准备 | 一百词作为内部事务候选；最多建立两百张独立卡，单词音频每词一份；提交成功才报告新增／已有 |
| 桌面合成 | 既有 Sherpa-ONNX／Supertonic 3，CPU 常驻模型 | 首个测量候选为一个后台合成名额，加一个保留的交互名额；两推理线程、关闭空转沿用既有实验方向，需产品复验 |
| 任务顺序 | 当前点击优先，批量单词优先于非当前例句 | 尚未开始的需求可提升优先级；不宣称当前版本可以中断在途推理 |
| 例句准备 | 当前卡及少量后续实际候选卡按需预取 | 七天到期范围只作候选过滤，不能等同于全部生成；播放前重查有效期 |
| 网页语音 | 浏览器有效缓存优先，缺失时调用已准入在线 TTS | 默认候选不要求 Drive 音频同步；长期凭据经 BFF；同步单词音频作为可选增强 |
| 文件保留 | 单词由生词归属保护，临时单词／例句按类型过期 | 归档／暂停不自动删除；浏览器缓存不具有桌面文件的永久保证 |

### 草案中需要校正的事实

| 草案假设 | 核验与处理 |
| --- | --- |
| 单词合成 25–40 ms，一百词 2.5–4 秒 | 现有八步实测不支持；下面的二十四请求热批量已需要 5.583 秒。不能把并发吞吐折算成单次延迟，也不能承诺刚进入复习时所有词音频都已准备好 |
| 两线程为前台保留至少 75% CPU | num_threads 控制推理会话线程，不是 CPU 份额；同模型多会话、并发调用与系统调度仍争用 CPU。低线程优先级只是辅助措施 [S1] |
| P0 入队后至多等待 30 ms，或可以抢占 P1 | 优先级只能改变未开始任务的次序；当前固定 Supertonic 回调在一块合成后调用，忽略其返回值，不能用返回零实现抢占 [S13] |
| 主线程十毫秒更新一百条 FSRS 初始排期 | 不应在 UI 主线程做存储；新卡 due_at 为 None，初次评分才产生排程。短事务用真实提交时间验证，不预设十毫秒 [当前进度读取](../../../crates/storage/src/review.rs) |
| 所有七天内到期例句都值得提前生成 | 到期不等于实际出卡；暂停、额度和评分均影响需求，且提前七天生成可能在使用前过期 |
| 独立缓存库加 WAL 消除全部锁竞争 | 可降低特定数据库争用，不能隔离 CPU／磁盘；WAL 仍只有一个写者，可能返回 busy，且有 checkpoint 成本 [S14] |
| 5000 词只占十 MB，单包永久不超过二十 MB | 当前接受的是 48 kbit/s；既有词样本估算 5000 词单声线约 43.9 MB 内容。容量随词数、长度、声线和版本增长 [空间实测](../tts-generation/gpu-cache.md) |
| 免费代理及 Web Speech 都能进入相同缓存流水线 | 未指定代理不能作为已准入兜底；Web Speech 没有标准音频字节导出接口，不能按同一路径缓存合成文件 [S16] |

## 现有测量能支持的结论

已有同机 CPU 独立实验支持常驻模型复用，但没有完成“批量生成同时查词／交互 TTS”的产品验收。[本地模型实验](../tts-generation/README.md)及[原始摘要](../tts-generation/results.json)：

| 配置 | 24 请求热批量中位数 | 完整进程中位数 | 采样私有提交峰值 |
| --- | ---: | ---: | ---: |
| 一个模型，串行，四推理线程 | 23.351 秒 | 25.850 秒 | 774.0 MiB |
| 一个模型，十二路共享，两推理线程，关闭空转 | 5.583 秒 | 9.845 秒 | 1,220.2 MiB |

这些来自 Ryzen 9 8945HS、八核／十六逻辑处理器、32 GB RAM，固定模型、八步和有限法语输入；24 请求重复使用十二词。另一组十二词对照中，单条推理中位数约由串行 0.98 秒增至十二路满载 2.69 秒。热吞吐、推理时间与点击到出声的延迟不能互换，也不能直接外推一百个不同单词的完成时间。

ONNX 官方说明，会话线程池可能彼此争用 CPU；线程空转消耗资源，支持限制线程和关闭空转。[S1] 因此“两推理线程”不等于整个应用只占两线程，也不能简单用任务数乘线程数保证剩余核心。

## 场景一：批量工作时继续查询和交互 TTS

推荐先采用**应用拥有任务、一个常驻模型、交互与后台分队列、有界后台并发**；若实测交互延迟仍不能接受，再比较双进程模型隔离。

### 分开定义响应和出声

“点击后 100 ms 内显示已接收／准备中”可以作为待验收的交互目标；它不表示音频已合成或开始播放。至少分别记录点击到界面反馈、查词完成、缓存命中到开始播放、缓存未命中到开始播放，以及批量总时间。缓存未命中包含排队、推理、编码、发布和播放准备，不能承诺零等待。以固定设备的分布及最大值验证；样本不足时不报告虚假的 p95。

1. 将批量任务所有权移到 Rust 平台层／应用生命周期。页面只订阅进度，切页继续任务；离开守卫继续保护未保存编辑，后台生成不再阻止导航。不能仅去掉 batchBusy 而保留卸载后的异步界面回写。
2. 查词、未来翻译请求、已缓存音频读取独立执行。读取缓存先于推理排队；合成期间不持 SQLite 写事务或缓存目录锁。翻译网络等待不能占合成通道。
3. P0 为查词、翻译和当前卡实际点击的音频需求；P1 优先生成批量单词，随后生成有预算的近期例句。首个候选同时最多一个后台合成和一个交互合成；后台不占用交互保留名额。相同语义键的请求合并，交互提升未开始任务；同一音频已经生成中则复用该任务，不再启动一个重复副本。
4. 需求可持久记录，但仅按可用名额逐词投递，不能提前提交一万条 Promise 或阻塞任务。首轮比较后台一／二／四路，保留交互名额；有交互时减少新后台投递。空闲提高并发也须验证恢复交互后的首条延迟。十二路只作吞吐对照，不直接作为产品默认；在线请求另有并发、配额和超时预算。
5. 已开始的推理不能靠优先级立即抢占；保留名额也不等于隔离 CPU。对比批量关闭／开启时的查词、评分、缓存播放和交互 TTS 端到端时间，再选择后台上限。有限的同机 CPU 不支持未经测量的“延迟完全零影响”承诺。

| 执行方案 | 优点 | 代价与适用条件 |
| --- | --- | --- |
| 单个常驻模型、两级队列、保留交互名额 | 延续已有共享模型实验，减少模型副本 | 在途后台请求仍争用 CPU；须验证固定运行库的并发正确性和交互时延 |
| 单模型严格串行、交互优先 | 内存及实现成本低 | 最坏仍等待当前单词；不适合作为严格低延迟并发保证 |
| 交互与后台各一个常驻进程／模型 | 没有共同生成锁，故障及调度边界更清楚 | 多一份模型；CPU仍共享，后台仍需限流；双实例峰值和收益未测 |

任务调度参照 Tokio 的有界 CPU 工作及专用线程建议，以及 MIT 的 p-queue 优先级、并发和背压设计，不引入其依赖、不复制代码。[S2][S3] p-queue 本日查询为未归档、MIT，最后 push 为 2026-10-16；其 README 表明功能已完善，不承诺新功能开发。

“插队”只作用于未开始的生成；当前固定运行库的 Supertonic 路径既不提供暂停恢复点，也没有实现回调返回零的停止行为。[S13] 不从其他模型的回调契约推断本模型可抢占。长句应作为独立请求，限制长度及执行预算；需要真正故障停止时由 supervisor 回收进程，不能把半段音频发布为成功。

本地工作繁忙不自动判为引擎故障。在线兜底仅在服务已配置、外发文本与费用行为已明确且错误适合切换时使用；用户也可明确选择交互走在线。MVP 不默认同时启动本地和在线竞速；若以后采用，需要处理重复费用、无法取消的在途合成和胜出文件的真实来源。在线仍有网络和服务延迟，不能称为“零等待逃生”。

### 缓存库与锁的选择

首期优先保留已验证的文件原子发布，用户库只存小型任务／引用元数据，短事务之外合成和读写音频。**不把拆出独立数据库或改成 BLOB 作为并发修复的前提。** 如果真实测量显示音频元数据写入拖慢笔记／评分，再比较独立缓存库；跨库归属更新需要恢复机制，WAL 下多个 ATTACH 数据库不是一个跨库原子事务。[S14]

SQLite 官方的小 BLOB 实验提供了内置 BLOB 可能更快的依据，但来源是特定旧版 Linux／文件系统测量，并明确要求在目标硬件复验。[S15] 两种存储均需比较实际安全读取、发布、清理、文件分配、事务持锁及恢复；WAL 的单写者、长读阻碍 checkpoint 和 busy 路径不能省略。低 OS 优先级也不替代有界调度。

## 场景二：批量创建和生成

### 分页、事务及合成并发分别控制

结合用户补充，建议先采用**仅选择当前页**：全选标为“选择本页”，换页、改搜索或筛选时清空未提交勾选；提交时固定所选 ID 快照，后台任务不因之后翻页而取消。页容量可从二十／五十／一百条评估，用户可只选一词。只有明确不跨页保留选择，分页才真的间接限制一次操作的词数；跨页勾选会改变这一结论。当前源码没有分页，本文提出的是后续交互方案。

因此不需要再叠加一条相同的一百词产品限制。页容量控制展示和选择，短事务控制数据库持锁，合成并发控制 CPU；三者独立。多页连续提交仍会累积需求，应通过持久需求去重、有限内存投递和总资源预算保持背压。后端仍校验输入数量和 ID；当前队列 skipped 的一万项界限不能直接当作批量加入 API 限额。

| 层次 | 建议 |
| --- | --- |
| 用户一次选择 | 推荐本页范围，不设最小选择数；一百／一千／一万词保留为后端和累计多页压力验证规模，不要求界面一次勾选一万词 |
| SQLite 提交 | 单连接、初始每一百词短事务；每词 savepoint；提交失败时该事务内不能报告成功 |
| 模型调用 | 每词一项，常驻模型复用，有界调度；两卡共用一份单词音频 |
| 例句语音 | 当前卡及少量后续候选按需准备；七天过滤不等于生成全部候选，不阻塞建卡 |
| 界面通知 | 合并计数和状态变化；不为每词全量更新大列表或刷新整个复习队列 |

已有 SQLite 实验比较了一百与五百词事务，一百是缩短持锁的初始折中，未证明其交互表现最优。[批量证据](README.md) 批量调度也不等于把所有词拼成一段语音再切割；当前入口是逐文本生成，未经验证不改模型输入与音质。

### 两阶段和任务状态

- **先建卡并提交，再生成语音。** 平台工作线程批量创建独立双卡，现有卡不重置，缺失进度的新卡保持 due_at = None；不能在加入时模拟评分或修改为“七天内到期”。逐事务反馈真实新增／已有／失败数，已提交且合格的识义卡可复习；缺词音频的听音卡显示待生成，保留身份、进度和主动暂停。重复加入或重试保持 [ADR 0005](../../adr/0005-independent-progress-for-vocabulary-card-types.md)。
- 使用 queued → running → ready，以及 retry_wait／failed／cancelled 状态；分开统计“建卡成功”“语音可用”“失败”“剩余”。成功音频先验证、原子发布，再更新引用和发合并通知，禁止先报可用。
- 为可靠重启恢复，建议在建卡短事务中原子记录最小的音频需求／任务，包含任务身份、目标资产、尝试次数及取消状态；启动后核验文件，再恢复未完成需求。文件发布与 SQLite 提交不是同一事务，须覆盖两者之间崩溃的恢复。
- 若第一阶段沿用无任务表的更小方案，应明确仅从已提交卡片和缺失音频发现待处理项、允许人工重试；不能宣称准确恢复原批次进度、取消状态或自动续跑。
- 偏好按任务创建时快照固定；声线切换沿用现有“不自动改写已保存音频”。已有有效音频直接复用，显式重生成另记需求；不能因模型升级全库自动重生成。

单词全量准备是合理的后台目标，但不是开始复习的先决条件。用户打开当前卡时，对缺失单词音频提升优先级；随后卡按有限窗口预取。就算整批还未完成，也能先处理正在使用的词，不依据未经验证的三秒估计等待整批就绪。

### 七天到期窗口改为需求筛选

保留 due_at <= now + 7d 作为**已有排程例句的宽候选条件**，但它不是实际出卡资格，更不是全量生成指令：

1. 新卡 due_at 为空，按真实新卡候选和额度处理；已学卡按真实排程处理。考虑暂停、当前会话跳过、额度、例句是否完整及内容修订，不修改排程来满足预取条件。
2. 优先准备当前卡和接下来三张实际候选卡；按音频语义键去重，两张同词卡不重复生成同一单词。由于尚无词音频的听音卡会被可评分队列过滤，需求发现还须从已建卡及缺音频状态取待生成项，不能只读已合格队列而永远漏掉它们。
3. 七天是候选范围上界，生成时机宜更贴近当前会话；若加空闲预生成，可先评估当天／次日和明确预算。现在生成、七天后到期的例句会在到期附近失效；同为七天的 horizon 和 TTL 没有有效期余量。计划使用窗口要落在资产 expires_at 前，并保留余量，过期则重新按需生成。
4. 评分、撤销、暂停／恢复、例句编辑和队列变化触发需求重算；启动／恢复用于补偿。不要只依赖每日启动巡检，也不要每次事件扫全库。取消尚未开始的陈旧预取；当前实际播放保持稳定，之后取卡使用新需求。

例句缺失或生成失败不会阻止识义卡和已具备单词音频的听音卡复习；不能把背面例句音频提升为新的评分门槛。后台单词优先，当前点击的例句提升为交互；持续新增单词时仍给已需要的例句有界机会。

### 重试、停止和退出

| 失败类型 | 建议行为 |
| --- | --- |
| 单词输入非法、资源缺失／哈希失败、权限或磁盘空间问题 | 保留具体失败；修复条件后人工重试，避免持续自动重试 |
| worker 意外退出或暂时失败 | 受控重启；同一失败只允许有界重启／重试，次数和延时是待验证参数；不能无限重启 |
| 缓存发布失败或替换失败 | 保留旧可用音频及已提交卡片；失败归到对应任务 |
| 未来在线 429／暂时网络或服务失败 | 尊重 Retry-After（若有）及提供商规则；有限退避并加抖动；鉴权、硬配额和参数错误分别显示，不一律按临时失败重试 [S17] |

“停止剩余生成”只停止未开始工作；正常正在生成的词完成后原子发布，不删除已完成音频或卡片。用户按词重试提升优先级并合并重复需求。

重试方案可以沿用草案的二／八／二十秒作为待测间隔，但需明确**首次调用加三次重试，最多四次调用**，不能同时写成“最多三次总尝试”。每项、每引擎和整批设总尝试／时间预算，切换一次后不在两引擎之间反复往返；在线服务持续不可用时暂时停止整批自动请求，防止一百词各自形成重试风暴。磁盘失败不是切换在线引擎能解决的问题；本地输入处理失败也保留真实错误，不假定都是 G2P。

FAILED 保留卡片、旧可用音频和诊断；当前卡点击或明确重试创建一次 P0 需求，不因每次队列更新自动重启失败任务。成功在线文件按其实际引擎和声线登记，不能伪装成原 Sherpa 资产。

Tokio 官方明确，spawn_blocking 开始后 abort 无效，shutdown_timeout 也不停止它。[S2] 持续 worker 应由专用线程／子进程 supervisor 管理；取消前端等待不等于取消合成。超时或退出时，由拥有进程的 supervisor 限时停止并回收本次进程树，保留错误。产品超时按词长与实测选择，实验／后端测试仍遵守硬性六十秒，编译另计。

## 音频保留、去重与身份

1. 把**生成语义键**和**文件内容 SHA-256**分开。前者包含完整 NFC 文本、合成语境、语言、实际引擎／模型及前处理版本、具体声线、合成参数和编码配置；建议复用现有 SHA-256，对有明确字段及规范编码的结构求 hash，不为此引入 BLAKE3。后者校验实际文件并供跨端下载去重。同语义的随机合成可能产出不同字节，以已保存引用为准。
2. 保留重音、大小写和撇号，不使用去重音搜索键当音频身份。当前单独字母 y 会改用 i grec 合成，语境及前处理规则必须入键，不能误用于代词读音。
3. 持久保留以**存在生词记录**为条件，不以是否已有听音卡为条件。收藏时把可复用的临时单词音频登记为生词归属；没有音频无需因收藏动作强制生成。暂存／生词归属不加入合成语义键，才能原地复用相同单词资产；独立词头与例句中的读音语境、原文与 IPA 输入则不能随意互换。播放的 0.6 倍速不产生另一个合成键。
4. 单词资产以生词归属保护；例句与临时查询资产保留自己的有效期。可用 expires_at = NULL 表示被持久归属保护的资产，但不能只靠一行 UPDATE：还要记录谁持有它。存在任一有效生词归属时不得删除；去掉一个归属不能删除其他记录仍引用的文件。例句不能因出现在闪卡背面而获得永久保留。
5. 推荐新增音频目录／元数据职责，但保留 portable 数据根、安全句柄、nofollow／重解析点检查、输入限制、原子发布及真实诊断。先让旧清理器跳过仍在生词本的词音频，再登记或安全迁移；失败保留原文件，不先删旧缓存。
6. 损坏的持久音频允许重生成，不改学习进度。永久保留不是无限保留所有声线／模型历史版本；旧版本替换和删除生词后的音频处置须明确后再实施，本研究不删除任何文件。

当前规则下，暂停复习保留生词及音频；“归档”尚未定义为移出生词本，也不自动等同于删除。明确删除生词后是立即删除最后一份归属的音频，还是转为有界临时保留，仍需决定。草案的删除／归档级联不能覆盖 [ADR 0005](../../adr/0005-independent-progress-for-vocabulary-card-types.md) 和学习数据保留边界。

清理建议在启动后低优先执行，运行期间六小时可作为候选间隔，按 expires_at 索引分段处理；读音频时先判断是否过期，不等到下次 GC 才生效。生成、归属升级、读取和清理须协调，删除前重新核验归属及在途使用。文件方案须实际删除安全目录内的资产；BLOB 方案的 DELETE 通常只释放库内页，不立即缩减 .db 文件，VACUUM 会带来额外重写和锁成本。[S18] 不把草案一行 SQL 当作完整、安全、固定轻量的 GC，也不宣称六小时调度已经验收。

现有 [空间实验](../tts-generation/gpu-cache.md) 用一百二十八个词、两声线估计：一万词单份约 87.8 MB 文件内容、本机约 111 MB 文件分配；两卡及慢速复用一份。它不含模型、备份或数据库，不是任意词表和文件系统的保证。该体量说明同步复用值得保留为选项，不能据此保证所有移动设备容量足够。

## 场景三：WASM 网页复习端

### 默认候选：在线按需生成与浏览器缓存

结合用户希望网页端利用网络且默认不占 Drive 的设想，建议将**浏览器有效缓存 → 已启用的音频包／同步资产 → 已准入在线 TTS → 可用且明确启用的浏览器语音 → 不可用及重试**作为获取路径。默认不启用同步时，缓存缺失直接走在线服务。WASM 继续承载已验证的 FSRS；音频获取由 Web 平台适配器负责，不搬入共享调度核心，也不要求部署桌面模型。

这个默认候选成立的条件是：接受在线声音与桌面不同、接受文本外发和服务费用、有已准入提供商及可用凭据边界。联网是支持条件，不保证网络始终可用或在线一定更快。重复播放先用已有文件；BFF 是否另做音频缓存及其存储／流量成本要单独说明。“默认不占用户 Drive”不等于没有任何云端成本。

首期 Sheets 若承担同步，仍传学习内容与必要身份／元数据，不传音频字节；桌面已有文件不会因 WASM 联网而自动变得可访问。只有用户以后启用导出／上传，网页才能复用这些文件。

| 方案 | 更适合的条件 | 限制 |
| --- | --- | --- |
| 同步桌面已有音频 | 要求相同声音、复用已认可音频、可离线或反复复习 | 需要上传／下载和授权存储；首轮传输及浏览器容量 |
| 网页按需在线生成并缓存 | 通常联网、接受在线声音、有服务准入及费用预算，希望少做音频同步 | 首次网络延迟、额度／费用、文本传给服务、声线不一致、缺网无新语音；本轮推荐的默认候选 |
| 浏览器系统语音 | 未配置在线服务，且设备存在合适法语声线 | 不保证同声线或离线；标准接口不能取得合成文件进入 IndexedDB [S16] |
| 浏览器运行模型 | 要求网页独立本地合成，愿意下载模型 | CPU／内存、许可和跨设备音质另验；不纳入此次默认方案 |

如果更重视相同声线、已认可桌面音质和离线复用，则启用同步资产优先更合适；如果更重视减少跨端同步实现，则在线按需生成更直接。两条路径共用资产元数据和播放接口，但不同实际引擎／声线保持不同合成语义键。

Google Cloud TTS 是可核验的例子：官方允许将生成音频文件用于应用或媒体，适用其 Terms；提供 OGG_OPUS；传统合成的内容限制为每请求五千字节，具体声线有各自请求额度。[S4][S5][S6] 这不是“一百词”上限，也不证明任意 OpenAI 兼容服务都有 TTS。

Google 传统声线按送入合成的字符计费；其他模型计价及存储／网络费用另外核查。[S7] 重复播放已保存文件无需再次发合成请求。最终提供商、声线、音质、长期保存／跨端分发条件、可接受费用和实际区域仍待准入；不因一个服务示例自动选择所有在线 TTS。

### 当前卡与后三张的有界预取

当前卡缺音频时立即提升优先级，后续三张作为可调预取窗口；窗口不是一次并发四个请求。首个候选将在线请求并发限制为两路，并给当前卡保留能力，后台不得占满所有名额；后续预取按网络、配额和实际卡片速度调整，不保证二百至四百毫秒内出声。

预取只读取后端认定的当前候选／内容，不模拟未来评分，也不改变 FSRS、每日额度或队列持久顺序。按语义键合并需求；评分、跳过、暂停、编辑或切换会话后取消尚未开始的陈旧预取，响应检查请求身份和内容版本。正常后台更新不替换当前题面或重新播放。

取下一卡及点击播放时仍检查缓存和有效期：预取成功不等于播放时仍有效。缓存满或写入失败时，允许已取得的音频在本次内存播放，并明确未缓存；不能因此报告持久保存成功。离线仅使用已有有效文件，缺失时显示真实状态及联网重试。

Web Speech 的 getVoices 返回当前设备可用声线，列表可能变化；localService 区分本地和远程语音，不能一概认作免费、稳定或离线服务。[S16] 该 API 的标准接口是 speak／cancel 和播放事件，没有导出 PCM、Blob 或 AudioBuffer 的方法。它是独立播放兜底，不执行在线文件缓存流程，也不在预取期间偷偷朗读后续卡。听音评分须与本次实际开始播放和错误／取消状态联动，不能凭调用 speak 成功放行。未指定、未准入的“免费代理”不加入默认链路。

### 可选单词音频同步

建议只同步有持久生词归属的单词音频，不同步七天例句；不能只用 expires_at IS NULL 判断类型，因为需要同时验证资产确为单词、归属仍有效且文件完整。清单包含稳定生词／卡片身份、资产语义键、内容 hash、字节数、格式、实际来源／声线／模型、内容版本与必要有效期。本地自增 vocabulary_id 和绝对路径不能作跨端身份；稳定身份及同步冲突仍与 M4 一起确认。

容量应按实际已编码文件相加。草案的十 MB 估计在十六 kbit/s、平均零点八秒假设下可作理论量级，但当前接受的四十八 kbit/s 实测词样本平均约一点四三秒、每份约八点八 KB；五千词单声线估算 **43.9 MB 内容／55.5 MB 本机文件分配**。云端包主要按内容加索引估算，不把本机文件分配算作上传字节。[空间证据](../tts-generation/gpu-cache.md) 改为十六 kbit/s 需要重新试听和编码验收；词数、声线或历史版本增长后，没有永久十至二十 MB 上限。

| 形式 | 推荐用途 | 需要处理的代价 |
| --- | --- | --- |
| 单一可变 pack | 首次手工导入、一次性快照或明确单写者的简单备份 | 修改包需要重新上传新内容；多端更新要处理丢失更新、版本／索引一致性及失败恢复 |
| 内容不可变的分片包加清单 | 后续自动增量同步与按需下载 | 只上传新增资产／分片，增加清单、修订和安全边界；需选定同步冲突机制 |
| 单音频一文件 | 早期小规模或调试 | 内容独立，文件／请求数量较多；不直接假定大词库更高效 |

Drive 官方支持文件创建／更新、可恢复分块上传及 Range 部分下载。[S19] 上传的分块是同一次上传会话的恢复机制，不等于对现有包按新增单词自动做增量同步；Range 可以减少下载，但依赖可验证的包索引、偏移及版本。单包不是不可行，只是不应把“只需一个文件”当成没有同步复杂度。

drive.file 是用户授予应用的文件级访问范围，不能当作某一文件夹的沙箱；当前 Google 接入尚未实现，需要在 M4／M6 验证创建、重新授权、选取已有文件及跨端恢复。[S20] Drive 的 Keep Forever 历史修订会占空间，最多可保留二百个这样的修订；不能靠修订机制自动解决并发覆盖，也不能无限保留每次整包版本。[S21] 只在授权范围内管理应用资产，不以包整理为由删除用户其他文件。

### 网页端限制

- **存储可靠性：** IndexedDB／Cache 默认 best-effort，浏览器可回收；persist 可以被批准或拒绝，私密浏览通常结束即删除。[S8] 音频推荐在 Cache Storage 或 IndexedDB Blob 选一种保存，避免重复副本。生词音频不主动 TTL 清理，但网页副本不能承诺和桌面文件同等永久；保留桌面／授权服务端权威副本和恢复路径。
- **七天有效期：** 若采用绝对有效期，下载不重新起算；例句变更产生新语义键。页面／Service Worker 不是可靠定时服务，不依赖网页关闭期间精确清理；访问时拒用过期缓存，恢复运行后清理。
- **格式：** WebKit 官方确认 Safari 18.4 在 macOS Sequoia 15.4、iOS／iPadOS 18.4 增加 Ogg Opus 支持。[S9] 最低系统及浏览器须确认；旧系统可按需提供经验证的 AAC／MP3 衍生格式，不默认重复保存全库。格式探测不代替实际解码和播放。
- **自动播放：** 浏览器可能拒绝 play 并返回 NotAllowedError。[S10] 提供用户点击播放，保持机器合成标识；只有本次实际播放成功，听音卡才能评分，不能只凭下载成功放行。
- **网络与凭据：** 优先同源 BFF，调用在线 TTS、控制费用及返回音频；不把长期密钥放进网页／WASM／VITE。BFF 必须有输入校验、鉴权、限流和适用 CSRF 保护。[现有架构](../../architecture.md)、[Google 鉴权](https://docs.cloud.google.com/text-to-speech/docs/authentication)。跨域 fetch 音频还需要正确 CORS；直接公开或带永久凭据的链接不作为同步方案。[S11]
- **同步语义：** 卡片进度和音频可用性分开。离线时已有有效音频可播放；没有语音的听音卡保留但不能评分。音频清单冲突、删除／取消归属、服务端保留及导出恢复属于 M4／M6 待确认事项。

Supertonic 模型的 OpenRAIL-M 第六条说明，许可方一般不对输出主张权利，但输出使用仍须遵守许可；提供模型托管服务属于其 Distribution 定义，涉及额外传导义务。[S12] 只同步音频与把模型作为在线服务不是同一许可场景。当前准入缺口及机器合成披露沿用 [既有记录](../issue-14/supertonic-licenses/ATTRIBUTION.md)，没有扩大正式发行结论。

## 建议实施顺序与验收

1. **#24 桌面：** 任务脱离页面、分阶段短事务、常驻 CPU 模型、交互优先／背压、定向重试与停止；结合原工单实现通知合并及自动队列更新。每次队列更新仍完整核验音频，稳定空闲无新增队列 I/O，当前作答／播放不被通知替换。
2. **本次已确认保留规则：** 先保护已有生词音频，再接资产归属与分类型有效期；调整 RuntimeAdapter／IPC schema、存储及安全清理边界，保留失败上下文。
3. **M3：** 完成例句朗读准入后接需求筛选及短窗口预取，避免为七天后未必出卡的例句盲目生成。
