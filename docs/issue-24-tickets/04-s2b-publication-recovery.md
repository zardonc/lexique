# B04／S2b：按最新意图发布、更换与修复音频，恢复中断操作

## Parent

[#24 复习队列、选定单词音频与安全清理规格](https://github.com/zardonc/lexique/issues/24)。

## What to build

从实际生成／重试入口完成明确的音频更换与修复：成功验证并持久提交后才切换当前，失败／取消保持旧声音及学习数据。已知版本沿用原规格，未知坏legacy按确认例外提示并使用当前偏好；较新意图最终完成，过时／取消请求不能覆盖。启动恢复覆盖全部未完成发布，包括终态任务残留intent。

## Acceptance criteria

- [ ] 本票V04／V05与W06／L03改前检查有真实失败或明确原行为基线；请求／响应严格校验，UI区分更换、修复、处理中、未知规格提示和真实失败。
- [ ] 实际worker加载资源与持久完整规格相符；文本／模型／语言／声线／前处理／参数／编码形成语义身份，内容hash独立；同规格不同输出合法，旧规格不支持不静默改引擎。
- [ ] 需求、选择desired generation及执行代次独立；原operation重试不加选择代次，同规格共享订阅／取消后后继需求均最终得到有效执行，取消一个订阅不停止其他有效需求。
- [ ] intent持久后事务外tmp／sync／不可变发布／安全回读，完成事务匹配目标词、最新代次、有效执行、未取消及期望旧选择，才提交版本／选择并发通知；rename不冒充DB完成。
- [ ] 失败／取消／权限／磁盘／提交失败保留旧当前与卡片；迟到旧内容可登记未绑定但不覆盖。成功切换立刻建立最多一份上一版14天保护，幂等同版本结果不把当前列为上一版。
- [ ] 已知新格式修复沿原spec，模型不支持可见失败并要求显式升级；可用legacy原样保留，未知缺失／损坏可按当前偏好修复并提示输出可能不同，能力／危险路径错误不无限合成。
- [ ] 在intent、tmp同步、rename、回读及complete各断点实际中断／重启；包含failed／cancelled pending、原选择已变、同hash新实例、重复恢复及孤儿内容，恢复同样守卫且不重新计期限或复位预算。
- [ ] T24-A06、W03、W04、W06、L03、L04及原T07／T09／T11相应DB／FS／UI／原生验证通过；新旧音频hash、身份／进度和保护回读一致，实播及README要求检查单列。
