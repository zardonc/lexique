# B01／S0：复现队列与并发缺口，冻结隔离基线和资源预算

## Parent

[#24 复习队列、选定单词音频与安全清理规格](https://github.com/zardonc/lexique/issues/24)。

## What to build

提供一个可重复的隔离现状检查，使维护者知道当前取卡、评分、查词、缓存播放及批量语音的真实成本与失败状态。冻结后续优化的输入、阶段计数、独立参考结果和交互／事务／资源预算，复现已经存在的缺陷，并为各后续协议提供可控fixture和竞争屏障。

此票不更改产品查询、schema、音频选择、清理或UI流程。未实现的新协议红测归后续所属票在改前执行，不要求本票伪造不存在功能的失败。原已通过行为标明基线通过；不留下未归属的默认红套件。

## Acceptance criteria

- [ ] 使用新建隔离学习数据，固定当前二进制／模型／schema／参数、输入seed、设备／存储、WebView2／RTSS及缓存条件；不复制或发布用户库、真实学习内容或敏感诊断。
- [ ] 分阶段记录数据库打开／锁、SQL／返回行、JSON、排序／位置、文件读取／hash、IPC／UI、worker排队／加载／推理／编码／发布；并行累计时间与端到端分开。
- [ ] 复现双额度零时到期日内听音漏出等当前真实缺口，固定失败断言／命令；导航、批量、共享锁、自动更新已有支持与尚缺项分别记录，不把旧负对照或未实现行为误判为当前回归。
- [ ] 独立oracle读取原始权威状态而非候选分页／缓存／投影，覆盖新卡空progress／due、混合阶段、额度／暂停／跳过／时区、持久顺序及音频健康／未知损坏；固定随机操作序列。
- [ ] 为V01–V05与十二优先红回归准备可控时钟、worker、真实SQLite／安全文件fixture及发布／GC屏障；逐票标明改前验证负责人，未执行未来契约不计passed。
- [ ] 按V02／V03在实现前记录接受预算、样本、页容量／短事务／合成并发对照；CPU固定8步／48kbit/s，保留后台1／2／4及总并发1／2／3，交互／冷热／非静音／解码与纯fixture分列。
- [ ] 100／1k／10k词（每词两卡）及混合／积压／缺失状态有可重复基线；50k先作压力输入准备。已声明稳态分位数的case至少100次尝试并保存失败，不能以三样本报告p95。
- [ ] 原R／V／T／F和14项验收有当前状态及后续负责票；执行／原生每项硬60秒、预编译分开、长时分片，记录命令／断言／原因，停止本次进程并保留其他工作。
